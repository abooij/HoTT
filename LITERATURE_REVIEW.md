# Literature review of the additional Rocq code (`git diff 55b912c HEAD -- theories test`)

Scope: everything added on top of upstream Coq-HoTT at `55b912c`: `theories/Analysis/*` (11 files), `theories/DomainTheory/*` (3 files), additions to `theories/Classes/{interfaces/cauchy,orders/archimedean,orders/naturals,orders/rationals,orders/rings,theory/dec_fields}.v` and `theories/Modalities/ReflectiveSubuniverse.v`, plus two test files. Reviewed at commit `ad1bdd8`.

Method: the library was built with `bin/build` (Rocq 9.1). Every name registered in `theories/Analysis/Thesis.v` was queried with `About` (and, for the domain theory, with `Set Printing Universes`) in a scratch file. The statements below are the elaborated ones, including section `Context` variables that Rocq abstracts. Two claims were checked by compiling extra scratch files (see Findings 1 and 2). `Print Assumptions` on `exact_ivt`, `approximate_ivt_locator`, `banach_fixed_point`, `least_fixed_point`, `merely_locator_iff_signed_digits`, `locator_times`, `equiv_iteration_operator_contr_iterated_midpoints` and `cauchy_reals_to_field` lists only the library's standard axioms: `Funext`/`isequiv_apD10`, `istrunc_truncation`, the quotient/graph-quotient HIT constructors, and, where the statement takes them as arguments, `Univalence` and `PropResizing`. There are no `Axiom`s, `Admitted` or stubs in the reviewed files.

Literature access: arXiv, LMCS, Dagstuhl, Birmingham eTheses and Semantic Scholar were **blocked** by the sandbox network policy, so papers could not be read in full. Statements from those sources come from web-search snippets or from what I already knew, and are marked as such. Two libraries **were** cloned and read: TypeTopology (`martinescardo/TypeTopology`, `source/Various/Pataraia*.lagda`, `source/DomainTheory/`) and the HoTT book sources (`HoTT/book`, `reals.tex`). The thesis PDF in the repository (Booij 2020) was read with `pdftotext`. It is used as one source among others, and the comparison below does not take its word over the code.

## Summary of the most important findings

1. **Pataraia's theorem (`least_fixed_point`) assumes `PropResizing` that it does not need.** Its universe constraints force the carrier and the order into the universe of index types, so it applies only to *small* dcpos. I checked this: applying it to a dcpo with carrier above the index universe fails with a universe error. For small dcpos, Taylor's predicative argument goes through without resizing. I compiled a resizing-free proof of exactly the same statement, using the file's own `fixed_point_subdcpo` (axioms: only `Funext`). This matches Escardó and de Jong's TypeTopology module `Various.Pataraia-Taylor` (2024). The thesis (Thm 3.2.3) makes the same redundant assumption, and the code reproduces it faithfully.
2. **The thesis's approximate IVT (Thm 7.3.1) is wrong as written, and the code silently fixes it, but proves a weaker statement than the literature.** The thesis takes the point to be the limit of Frank's interpolating bisection. Here is an explicit counterexample, worked out by hand and not formalized: ε = 1/2 on [0,1], with f piecewise linear through (0,−1), (0.05,1), (0.3,1), (0.5,0.2), (1,1). The limit is 0.05, where f = 1 > ε. The code instead proves that the limit *or one of the midpoints* works (`approximate_ivt_candidates`). However, in `approximate_ivt` and `approximate_ivt_locator`, f is a total function `F -> F` and the conclusion `hexists y, |f y| < e` **does not say y ∈ [a,b]**. That is weaker than Frank (LMCS 2020, Thm 1.1) and Bishop–Bridges, where f is defined only on [a,b], so the point lies in [a,b]. The candidates do lie in [a,b], but the code does not state it.
3. **None of the hypotheses of the analysis development are ever instantiated.** The library has no `Rationals` instance, no `OrderedField` instance, no instance of `ArchimedeanProperty` or `IsComplete`, and no enumeration `nat <~> Q`. `CauchyReals` is only a quotient type, without field structure or completeness. There is no interval object and no initial Cauchy structure. Every analysis theorem is therefore conditional on an abstract Q and F whose joint existence is not formalized here. They are satisfiable mathematically (for example, the Dedekind reals with the usual ℚ).
4. **Several statements carry hypotheses that do not occur in them.** `merely_locator_iff_limit` states nothing about integers or digits, yet requires a model `Z` of the integers, a base parameter `d`, a proof of `0 < d` and `Univalence`, because the proof routes through signed digits. `locator_signed_digits`, `signed_digits_locator` and `merely_locator_iff_signed_digits` also require `Univalence`, which nothing in `LocatorDigits.v` visibly uses. It is probably used only to obtain `Funext`, though I did not verify this.
5. **Otherwise the definitions match the literature, with structure and property placed correctly.** This covers locators (Booij, MSCS 2021), Cauchy approximations, limits and Cauchy-structure laws (HoTT book §11.3, written with `e + d` in place of `ε − δ`), and dcpos, directedness and Scott continuity (de Jong–Escardó; TypeTopology `DomainTheory`). It also covers interval objects (Escardó–Simpson, LICS 2001), metric spaces (HoTT book §11.5), and Banach's theorem, both in Bishop's form and in the thesis's pseudometric form. Other places where the code silently corrects or strengthens the thesis:
   - The Cauchy-reals relation (thesis Def 4.4.9 has the typo y_{M(ε/4)} and no absolute value).
   - The exact IVT now also gives a ≤ x ≤ b.
   - Banach needs only d(Tx₀,x₀) ≤ C, not a bounded space.
   - Signed digits are generalized to any base 1+d.
